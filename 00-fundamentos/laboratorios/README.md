# Laboratorios

Los laboratorios integran varios fundamentos en una sola práctica. En esta etapa el resultado principal **no es código**: es un análisis comprensible, comprobable y suficientemente claro para convertirse después en pseudocódigo.

## Laboratorios disponibles

1. [Sistema de turnos de atención](01-sistema-turnos.md)

   Analiza un proceso con prioridad, reglas y múltiples escenarios.

2. [Revisión de una solución defectuosa](02-solucion-defectuosa.md)

   Detecta problemas de secuencia, validación y control de aforo.

3. [Propuesta de una solución pequeña](03-propuesta-solucion.md)

   Diseña desde cero una especificación inicial de un problema cercano.

## Evidencia mínima

Para considerar un laboratorio completado, debería incluir:

- problema y objetivo delimitados;
- reglas, restricciones y supuestos explícitos;
- descomposición y secuencia principal;
- entradas, validaciones, proceso y salidas;
- casos normales, límite e inválidos;
- dudas o situaciones todavía no resueltas;
- aprendizaje obtenido durante la revisión.

Puedes usar la [plantilla de evidencia](../plantilla-evidencia.md).

## Revisión final

Antes de cerrar un laboratorio, comprueba:

- ¿el problema está delimitado?;
- ¿las reglas fueron declaradas?;
- ¿los pasos respetan sus dependencias?;
- ¿los casos de prueba tienen resultado esperado?;
- ¿otra persona puede entender la explicación?;
- ¿se identifican las dudas pendientes en lugar de ocultarlas?

Después utiliza el [checklist de avance](../checklist-avance.md).
